# 360° Audit — Web UI + API Layer

**Date:** 2026-07-29
**Scope:** FastAPI app, SSE/WS chat, static JS/CSS, auth/sessions, SSRF, path
traversal, secrets in responses, CORS, cookies, rate limiting.
**Method:** OWASP-focused read of `kazma-ui` + its security deps in core/gateway.

---

## Executive Summary

**The Web UI is materially better hardened than the typical "agent on a port"
codebase.** No stored-XSS, no SSRF bypass, no path-traversal escape, no raw-secret
disclosure found. The XSS surface (the biggest concern) is properly closed:
agent/tool output renders through an HTML-escaping markdown renderer (`streaming.js:203`),
tool results are escaped, no raw `innerHTML` of untrusted content.

Three **Medium** residuals (CSRF breadth, CORS override, no DoS cap on streams)
and several low smells. **Overall: 78/100.**

---

## Findings

### ✅ W1 — XSS — SAFE
- `streaming.js:203-324` `KazmaStream.markdown` HTML-escapes **first** (`esc()`), then applies inline transforms. Raw `<script>`/`<img onerror>` → inert text.
- User msg → `escapeHtml` (`chat.js:1528`); assistant → `KS.markdown`. Tool results → `escapeHtml` (`chat.js:1737,1756`).
- Link `href` uses `esc()` + scheme allowlist (`http(s)`, `mailto`, same-origin) (`streaming.js:286-300`).
- **Smell (low):** `swarm.js:2294,2565` take pre-escaped HTML by convention (callers pass `esc(...)` output). Safe today; fragile if a future caller forgets. Recommend these functions take plain text.

### 🟧 W2 — CSRF — Medium (breadth gap)
- Broad `/api/*` mutating endpoints rely **only** on `SameSite=Lax`. Only the email router has a real Origin/custom-header check (`email_api.py:134-163`).
- `SameSite=Lax` blocks cross-site fetch but allows top-level `POST` navigations. Most Kazma endpoints expect JSON (→ CORS preflight blocks cross-origin), which is an effective secondary barrier — but depends on CORS config.
- **Fix:** lift `_verify_same_origin` (Origin/`X-Requested-With` check) to all mutating POST/PUT/PATCH/DELETE.

### ✅ W3 — SSRF — SAFE (well-protected)
- `security/ssrf.py:validate_url` blocks non-http(s) schemes, loopback/RFC1918/link-local (incl. `169.254.169.254`), and **walks every A/AAAA record** (mitigates DNS-rebinding). Redirects re-validated (`read_url.py:650-652`).
- **Smell (low):** TOCTOU between `validate_url` (resolves DNS) and httpx (resolves again). Robust fix: resolve once, pin IP. Not currently exploitable.
- **Deliberate trust boundary:** provider `base_url` uses `allow_private=True` (`sse_chat.py:1586`) for local Ollama/LM Studio — an authenticated operator can point the LLM at an internal address (exfils the API key sent there). Document it.

### ✅ W4 — Path traversal via API — SAFE
- IDE API delegates to `IdeService.resolve()` (the hardened two-layer path). Workspace API uses `resolve_active_root` + `_is_within_workspace` (`target.resolve().relative_to(workspace)`).
- **Smell (low):** `/api/workspace/files` returns absolute `root` path in JSON (`workspace_api.py:153`) — minor info disclosure. Return only a display name.

### ✅ W5 — Secrets in responses — SAFE (masked)
- `/api/github/status` returns `has_token: bool`, never the token. `/api/provider/active` masks `api_key → "***"`. Settings export masks recursively (`settings.py:44-85`).

### 🟧 W6 — CORS — Medium (override risk)
- `allow_credentials=True` + fixed origin list (localhost ports + `kazma.ai`) (`app.py:410-416`). Fine if trusted — but `KAZMA_CORS_ORIGINS="*"` env override + credentials = insecure config.
- **Fix:** reject `*` when `allow_credentials=True`.

### ✅ W6b — Defaults — mostly safe
- Default host `127.0.0.1`; `0.0.0.0` without `KAZMA_SECRET` warns but doesn't refuse (`app.py:1514`). HTTPS not enforced (cookie `Secure` set only under HTTPS via `X-Forwarded-Proto`). Expected for localhost; terminate TLS at a proxy for remote.

### ✅ W7 — Static files — SAFE
- `StaticFiles` mount rejects `..`; `/favicon.ico` is a fixed FileResponse. No custom path logic.

### ✅ W8 — Deserialization — SAFE
- All YAML uses `safe_load`; no `pickle`/`eval`/`exec` of request data.

### 🟧 W9 — DoS — Medium (no stream cap)
- Login: IP rate-limited (10/5min). **`/api/chat/stream` (SSE) and WS chat: no per-client concurrency/turn-rate limit.** A session can open unbounded SSE connections and exhaust FDs/checkpointer. Upload has a 20MB cap.
- **Fix:** per-IP/per-session concurrent-connection cap + turn-rate limit on streams.

### ✅ W10 — Cookies — correct attributes
- Opaque session cookie: `HttpOnly`, `SameSite=Lax`, `Secure` (under HTTPS), 14-day TTL. Legacy `kazma-secret` cookie (value = secret) is fallback-only on exception path.
- **Smell (low):** 14-day TTL, no rotation/rotation-on-privilege-change.

## Roadmap

### ⚡ Phase 1
1. **W9** — per-session concurrent-SSE/WS cap + turn rate limit.
2. **W6** — reject `KAZMA_CORS_ORIGINS=*` with `allow_credentials=True`.

### 🏗️ Phase 2
3. **W2** — global Origin/`X-Requested-With` check on mutating endpoints.
4. **W1-smell** — make `swarm.js` terminal-line functions take plain text.
5. **W4-smell** — drop absolute `root` from `/api/workspace/files` JSON.
