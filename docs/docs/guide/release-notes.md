## What's new (2026-10-10)

Telegram, Discord and Slack preserve finalized answer text and save one reply
per turn. English/Arabic literal-JSON copies and one-paragraph prose requests
have conservative formatting safeguards; ambiguous tool-argument fragments
receive one bounded recheck without executing text. Web/Telegram code delimiters
and saved terminal history preserve their contents. Structural answer-quality
signals are available to administrators, separately from accuracy grades.

Native command registration and private reply delivery, IDE draft protection,
durable retry receipts and Windows-service Docker execution were also updated.
The owner's 60 development and 24 fresh bilingual responses are fully reviewed;
approved replacements remain separate from the original failed responses.
The operational pilot is in progress through 2026-10-17. Neither these small
review sets nor live smoke checks establish a production accuracy or uptime SLO.
See [Recent features](recent-features), [Native chat commands](../ops/native-slash-commands)
and [Known gaps](https://github.com/Mubder/kazma/blob/main/docs/KNOWN_GAPS.md).

## What's new (2026-10-04)

Settings now require durable storage: boot stops if settings cannot initialize,
and operational save failures return HTTP 503. Restore storage, reload and
review values before retrying; a lost acknowledgement may follow a committed
write. See [Configuration](configuration#settings-durability-and-outage-recovery)
and [Troubleshooting](troubleshooting-and-workarounds#settings-save-failed).

Real-model evaluations now pin a provider/model and use isolated stores with
fixture tools. Mechanical results are separate from human-reviewed bilingual
holdout accuracy, which remains unmeasured without reviewed cases. The default
prompt separates source facts from inferences; this is not accuracy certification.
See [Recent features](recent-features), the
[evaluation workflow](https://github.com/Mubder/kazma/blob/main/docs/DURABLE_SETTINGS_AND_LIVE_EVAL.md)
and [X Studio dataset collection](x-evaluation-dataset).

It now counts what the Hygiene purge takes, and a redirect is listed as "merged into" its target. A merge also refreshes the counts of the entities linked to both names, and a maintenance pass fixes any stored count that disagrees with memory: 11 of 377 entities on the live install showed wrong counts ([Memory & RAG](memory-and-rag)). |

The owner's names now come from the memory hub, on any install. Both purges (the Memory page's and the agent's) also deleted merge redirects, the rows that send a merged name to its target; they now remove only empty shells. The Entities search finds an entity by its own ID ([Memory & RAG](memory-and-rag)). |
| **The memory graph shows what memory holds** | Most nodes the Memory graph drew alone were made by the drawing. The links joining a concept to you were the first dropped when the graph had too many facts, a cut by node left a fact's subject alone, and values such as `true` disappeared. The graph now keeps connected groups whole, starting from you, and draws each value on its own fact. On the data side, an automatic merge of two names for one thing failed on every install and left a duplicate; it now works. Work items such as phase names, tickets and versions no longer become entities (their facts are kept), an entity whose last fact is removed goes with it if it holds nothing else, and memory health lists the remaining clutter with examples ([Memory & RAG](memory-and-rag)). |
| **A chat opened from another page shows its turn live** | Going to Chat through the sidebar from another page left the chat unable to draw a turn. A task you sent ran, and even paused for your approval, while the chat showed nothing until a refresh. The sidebar swaps pages without reloading them, and it skipped the folder of scripts Chat draws turns with. Those scripts now load the first time a page needs them, and a test checks that every page gets every script it includes ([Web UI](../products/web-ui)). |
| **The daily digest counts the whole day** | The morning digest on Telegram said "Turns completed: 0" over a day with four turns, and listed two maintenance pauses that had ended under "Needs attention". It read only the newest log file (the log starts a new file at midnight) and counted web turns alone. It now reads every log file of its 24 hours and counts the turns of every chat app ("Turns completed: 4 (web 3, telegram 1)"). Approvals come from the approval registry, one per question. Alerts are counted over the whole day, not only since the last restart. Reloads and maintenance pauses are listed as planned work, with the longest pause. A digest no channel took is sent again an hour later; it used to be marked as sent. |
| **Slack says when its app is full** | Slack lets one app hold ten connections at once. When all ten are taken, Slack refuses Kazma's until one frees, and meanwhile a message can go to whichever program holds a slot. Kazma now says so at the first refusal, as a warning and as the connection's problem in the Slack Test (Settings → Providers & Connectors → Platform Connectors). The Test shows the count and checks whether your latest messages reached Kazma ([Gateways & Platforms](gateways-and-platforms)). |

## What's new (2026-10-02)

They work now, Remove asks first, and the page's messages follow its language. In Settings → MCP the switch starts or stops the server at once and can show a server as off (it could not before); the dot shows whether the server runs (it was always red); and Test is the MCP page's Test (Settings' own copy failed for the filesystem server). `/config tools toggle` applies at once too. | **Every count reads right, in English and Arabic** | About seventy labels in the web interface had a number beside a word in one form: "1 msgs", "Plan locked (1 steps)", "N worker(s)", and in Arabic "1 أدوات", "2 أدوات" or "11 معتقدات". Every count in the chat, the Dashboard, the memory pages, Research, Time Travel, Documents, Knowledge, Settings, the Swarm page and the MCP pages now uses English's two forms and Arabic's six. | **Send a test alert** | Settings → Adapters & Routes → **Send a test alert** sends one message along the saved alert routes, the way a real alert travels, and the page names each route that took it ([Deployment](deployment)). |
| **A chat kept out of memory stays out from its first message** | "Don't remember this chat" set before the first message now holds: the memory writer checks every id the chat has. On the live install such a chat had reached memory through the catch-up sweep. |
| **Small fixes** | The SQL tools' refusal of one of Kazma's own databases names the SQL tools, and the Skills page no longer shows "v—" for a skill without a version. |
| **Updating packages: one command, and it works on Windows** | `kazma update` stops and restarts a supervised Kazma itself. It waits until no chat is mid-turn, has the guard stop the server and keep it stopped while the packages install, then starts Kazma again. A failed install keeps Kazma stopped, and the same command is the repair. It no longer replaces packages under a running server (on Windows that fails half way and leaves a mix of old and new packages). On Windows the update runs with the install's Python (`.venv\Scripts\python.exe -m kazma_cli update`): a reinstall must replace `kazma.exe`, which Windows does not allow while it runs, so an update started from `kazma.exe` refuses before installing anything and names the command. It used to fail on its own launcher and leave Kazma half installed. The "packages are behind" alert names the command ([Kazma update](../ops/kazma-update#the-server-is-stopped-and-started-for-you)). |
| **File tools no longer hold up every chat** | Looking up the workspace and your granted folders is a database read, and the agent's file tools did it on the server loop that serves every chat; so did the research pipeline, the MCP path check and the chat apps' sidebar sync. All of it now runs beside the loop. The SQL tools now open a relative path such as `app.db` in the workspace, like every other file tool. |
| **A message Kazma could not send is reported as not sent** | Reminders, files and scheduled-post notices were reported as delivered whatever Telegram, Discord or Slack answered. A refused reminder is now logged as failed, a refused post notice falls back to your other chat apps, and the agent is told when a file was not sent. `send_file` works again from reminders and the command line. |
| **Ops alerts from background work arrive** | Alerts raised by backups and boot checks were sent on the wrong event loop and reached nobody; one was the alert that your packages were behind. They are delivered on the server's own loop now, and an alert no chat app took falls back to a direct Telegram message. |
| **Agent skills show what activation will do** | Every list of agent skills (the model's catalog, `list_agent_skills`, `kazma agent-skills list`, the Skills page) shows whether a skill is verified, unsigned or refused, with the reason. A refused skill is no longer offered to the model as verified, and the Skills page no longer shows an invented "100/100" score. `kazma agent-skills sign` takes several folders ([CLI reference](cli-reference#kazma-agent-skills)). Only an attempt to use a refused skill is logged; listing them used to fill the log on every turn. |
| **Packages with known advisories are upgraded** | Fourteen packages with published advisories have new minimums, the lock file matches the project again, and the server says at boot when an install's packages are older than the build requires ([Security & Safety](security-and-safety)). |
| **An Approve click is never lost** | A turn shows its approval card, then finishes its own bookkeeping. An Approve clicked in that moment was refused as "no longer pending" over a card that was pending, so the button did nothing. The approval now waits for that bookkeeping and goes through. |
| **The Swarm page settles finished tasks** | A finished task's live view ends with its result even after a restart (before, it reconnected ten times and its timer kept counting), and a cancelled task's view ends too. The Workflow Editor and the Playground show the task's answer, which they never found. Running tasks the page did not start (another tab, a chat) appear in Active Tasks again; a hidden script error kept them out. |
| **Commands keep their files out of your repository** | A command the agent runs got your workspace as its home and temp folder, so tool caches and temp files landed in the repository (143 MB of `uv` cache in the live install). Each workspace now gets a private home outside it. |
| **Sending a task to the swarm from the IDE doesn't freeze chats** | It described the workspace (two `git` probes of up to 4 seconds each) on the loop that serves every chat; it now does that beside it. |
| **Searches skip what your repository ignores** | The agent's file search and the code index read the files your repository keeps: tracked files, plus untracked ones `.gitignore` does not exclude. In the live install a 4.7 GB clone, ignored by `.gitignore`, made one search take 13.9 seconds and return its matches; searches there now take about a second. A folder you name is still searched ([IDE](../products/ide)). |
| **The security report tells the truth; sign-in stays on behind a proxy** | The hardening report (`GET /api/security/hardening`) now measures what each check names: credentials written in the install's own files, MCP secrets outside the vault, who can reach the API, advisories for the package versions actually installed, skills that would be refused, TLS, the record of approvals, and calls that run a shell or evaluate code. It had reported critical failures that were not true, and passed checks on a keyword. `KAZMA_AUTH_DISABLED` behind a tunnel used to start with every API route open; it is now refused at startup when a proxy is declared, and a request that came through a proxy gets a 503 while it is set ([Security & Safety](security-and-safety)). |

| **A full audit of the code** | Every product and script file was audited ([report](https://github.com/Mubder/kazma/blob/main/docs/audits/AUDIT_FULL_2026-09-30.md)) and its findings fixed with tests — among them the removed semantic response cache, the Swarm page crash on quotes, Safari voice transcription, disk work that blocked the server, dead code and unused dependencies — and every `/api` route now has a caller or a written reason. |

## What's new (2026-09-28) — the memory program

| Area | Change |
|---|---|
| **Who Kazma is for, said plainly** | **One operator per install.** Whoever runs an install has full control, can switch any safeguard off, and answers for what its agent does; anyone they let in — a web login or an allowlisted chat account — acts with their authority. The safeguards protect the operator from the agent and the untrusted content it reads, not an install from its operator. Now the first section of the [Threat model](https://github.com/Mubder/kazma/blob/main/docs/THREAT_MODEL.md#who-kazma-is-for-one-operator-per-install), pointed to from the README and the feature list. |
| **An old "skip approvals" flag no longer lasts forever** | A YOLO flag set before windows had an end time was honoured for good — one chat of the live install had skipped approvals under one since July. Such a flag now counts as ended and is removed, and the 15-minute maintenance removes every ended window (90 had piled up). A running window is never cut short. |
| **`kazma project init` no longer over-promises** | The `.kazma/` templates said their rules were "applied to every agent session"; nothing in Kazma reads them yet — `init` creates them, `show`/`validate` check them. Each template now says so and links [issue #20](https://github.com/Mubder/kazma/issues/20); a test keeps the wording honest. |
| **Recall by evidence, memory made visible** | A memory is used only when it matches the question well enough — nothing is injected when nothing does. A turn that used memory shows a **Memory used** row in its activity: how many facts, conversation memories, weekly summaries and library passages the model was shown, stored with the turn so a reload shows it again. See [Memory & RAG](memory-and-rag). |
| **"About me"** | Settings → Memory → About me is a short text you write about yourself; Kazma reads it at the start of every reply, in every chat, and never fills it in itself. What you say in a conversation wins over it. |
| **Weekly summaries, "where are we with…"** | Once a week ends Kazma writes a short summary of each topic (what it was about, what was decided or done, what stayed open), on the Memory page and in the export. Ask where a long-running topic stands and those summaries are brought back — at most two, after the matching turns. |
| **You decide what Kazma remembers** | The Memory page lists what Kazma remembers of your conversations, each with **Forget**; a chat's menu can keep it out of memory (or `/memory off` on Telegram, Discord, Slack); deleting a chat can also forget what it learned; **Export** downloads everything. Kazma keeps one version of a fact — a new value replaces the old. |
| **Isolation and quiet** | Each tenant's memory stays its own; memory work no longer holds up other chats; removed memories can no longer come back through the Postgres mirror; compaction no longer keeps a copy of the conversation outside both controls. |
| **Databases that stay writable** | A failed write (lock timeout, full disk) no longer leaves its database locked — fourteen connections had the fault, now covered by tests that fail each write on purpose and a check on the source. Chat step history is bounded on Postgres too (newest 200 steps a chat, a setting — 0 keeps everything), and a model switch no longer leaks a checkpointer connection. |
| **Backups prove they restore, by default** | The weekly check restores the newest Postgres dump into a scratch database, verifies and drops it (`KAZMA_PG_RESTORE_REHEARSAL=0` opts out). Local + offsite snapshots run every 6 hours. See [Disaster recovery](../ops/disaster-recovery). |
| **The guard** | The supervisor's guard restarts Kazma itself, can no longer die unnoticed, and pages you over Telegram; deploy kills are not treated as crashes; a restart no longer runs out of time shutting down. |
| **Secrets and tunnels** | A password inside a provider or connector URL is treated as a secret and masked on every screen and API; web chat over Cloudflare Tunnel loses no approval cards and merges no turns; no more false "undeclared proxy" alarms behind a tunnel. |
| **Every environment variable described** | The [environment variables](../reference/environment-variables) page now covers every `KAZMA_*` name with where the code reads it — and a check keeps the page complete. |
| **Every known gap closed or accepted** | `docs/KNOWN_GAPS.md` opens with where things stand: no open defects known, two owner decisions, and the accepted limits with their reasons. See [Known gaps](https://github.com/Mubder/kazma/blob/main/docs/KNOWN_GAPS.md). |
